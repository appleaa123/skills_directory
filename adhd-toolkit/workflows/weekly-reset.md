# Workflow: Weekly Reset

**Route here from**: SCATTERED, when the ask is broader than one day — "help me get on top of things," "I feel behind on everything," a recurring check-in.

## The failure mode this avoids

A default weekly review tries to account for everything and restart everything — every dropped thread gets rescheduled, every open loop gets a new deadline. That produces a longer list than the one that caused the overwhelm in the first place. **Abandoning something on purpose is a valid, first-class outcome of this workflow** — not every dropped thread deserves to be picked back up, and treating the list as sacred is exactly what makes it unmanageable.

## Procedure

1. **List what's actually open** — everything currently unfinished, one line each, no elaboration yet. If [continuity.md](../references/continuity.md)'s `state.md` exists, read it first; it may already have most of this list.

2. **Sort each item into exactly one of three piles — no fourth option**:
   - **Restart** — still matters, genuinely worth resuming.
   - **Abandon** — say it plainly: *"This one's done, not because you finished it but because you're choosing to stop."* This is not a failure to record — it's a decision, and it deserves the same weight as a completed task.
   - **Not yet** — matters, but not this week. Different from abandon: it stays visible somewhere, just not on the active list.

3. **Don't ask "why did this stall?" for every item.** For most items the answer doesn't change what happens next. Ask it only for the one or two that are going in **Restart** — there, the reason matters because it might recur.

4. **Name what actually worked this week**, even briefly. A reset that only inventories what's broken reinforces the sense that everything is broken. One good thing, stated plainly, before moving on.

5. **Update `state.md`** (see [continuity.md](../references/continuity.md)) with the new Restart list and the Abandon decisions — abandoned items should not silently reappear at the next reset.

## Ends in

A shorter list than the one they arrived with, because Abandon is doing real work — and one explicit next focus for the coming week, not a rescheduled version of everything.
